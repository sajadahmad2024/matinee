# Material theming

The theme lives in `lib/core/theme/` as generated by bootstrap: `AppColorScheme` (enum, one seed per scheme), `AppColors` (`ThemeExtension` for tokens Material lacks), `AppTextStyle`, `AppSpacing`, `AppTheme` (assembles `ThemeData`), `ThemeCubit` with a freezed `ThemeState`, and `context.appColors`. Widgets only read the theme; every change below happens in that folder.

## Decide first

| Request | Change |
|---|---|
| New brand colour or a second selectable palette | New `AppColorScheme` value with its seed. `light()` and `dark()` derive the roles. |
| One Material role looks wrong for a scheme | `.copyWith(role: ...)` on the generated `ColorScheme` inside the enum, not in a widget. |
| A colour with a meaning Material lacks (success, warning, info, brand accent) | New field on `AppColors` with `light` and `dark` values, `copyWith` and `lerp` updated. |
| A font from the design | Add the font to `pubspec.yaml`, set `fontFamily` on `AppTextStyle._base`, adjust roles. |
| A component looks different everywhere | Its `*ThemeData` in `AppTheme._build`. Never style instances. |
| Dark mode issue | Check the `dark()` seed and `AppColors.dark`; never check brightness in a widget. |

## Figma variables

The variable-to-theme mapping tables live in the implement-screen skill (`references/figma-mapping.md`), which fills them before writing widgets. This skill owns only what the mapping produces: a new scheme, token, text role or component theme, through the procedures below.

## Procedures

**Add a scheme.** Add the enum value and its seed in `_seed`. The compiler flags every switch that needs the new case. Add a `ThemeCubit` test case if a scheme picker exists.

**Add a token.** Field on `AppColors`, value in `light` and `dark`, `copyWith` and `lerp`. Use through `context.appColors.newToken`.

**Persist the user's choice.** Inject `PreferencesService` into `ThemeCubit`, add `Future<void> start()` that reads the saved scheme and mode, call it from `App` with `unawaited`, and write on every `set*`. Test with a mocked `PreferencesService`.

**Verify.** `flutter analyze --fatal-infos`, then run the app in light and dark (`ThemeMode.dark` through the cubit) and check `context.appColors` contrast against `Theme.of(context).colorScheme.surface`.
